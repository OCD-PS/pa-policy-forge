# Frontend and capability audit

Baseline: `2574631`. This is a source/UI inventory, not a claim that every target API or configuration field has been validated on an appliance. The separate human-browser audit and backend/security work provide the end-to-end evidence.

## Surface inventory

| Area | Present in source / GUI |
| --- | --- |
| Profiles and collection | SCM, Panorama, standalone; active/passive serial and source-IP recognition; profile edit/delete; aggregate flows and manual purge |
| Policy runs | Per-profile run history, build/preview, candidate push, run deletion |
| Configuration source | Remembered full live XML pull or XML import; workspace versions; XML and set export; API push remains available |
| Policies | Security, NAT, QoS, PBF, decryption, application override, authentication; XML additionally exposes tunnel inspection, DoS and SD-WAN. The latter three are explicitly unavailable in SCM; SD-WAN migration remains excluded. Single and bulk editors share UI behavior. |
| Objects | Address/service/application groups, addresses, services, tags, regions, HIP, EDL, URL categories, security profiles/groups, schedules and log forwarding; predefined applications remain catalog items |
| XML Network | Interfaces, zones, VLANs, virtual wires/routers, logical routers, routing profiles, IPSec/GRE, GlobalProtect portals/gateways, DHCP, DNS proxy, QoS, LLDP, network profiles |
| XML Device | Setup, administrators/roles, authentication, certificates, local users, server profiles, logging, HA, User-ID and VM information sources |
| SCM Network / Device | Interfaces, zones, logical routers, IPSec, DHCP, DNS proxy, interface/zone-protection profiles; setup and HA. This is narrower than the XML surface. |
| Migration importers | 10 parser registrations: PAN-OS XML, Palo Alto CSV, Cisco ASA, Cisco IOS, Check Point, Fortinet, Juniper SRX, AlgoSec, Stonesoft, generic |
| Migration workflow | Optional device, offline base creation/import, source editors, collision search/merge, transformations, interface/zone mapping, analysis, candidate creation/review and XML/set export |
| Settings | HTTPS certificate installation and application-catalog credentials/refresh |

The baseline has 86 `route/get/post` decorators plus request/response hooks. Templates share one CSS file and one JavaScript file; the latter still contains separate live-policy, offline-policy and object-picker implementations.

## Fixed and regression-tested

1. Hidden required SCM scope fields were re-enabled on standalone/Panorama target forms, blocking native form validation and making Save appear ineffective.
2. Shift/Ctrl range selection selected filtered-out policies. Only visible editable rows are now added to a range.
3. Network/Device family tabs and text filters overwrote each other's row visibility. Both constraints now apply together.
4. In-page review links scrolled to collapsed editors without opening them. Links and direct fragment navigation now expand the enclosing details.
5. The review queue linked to an absent `best-practices` section. The existing analysis panel is available as a compact collapsed tool; the bulk disable action requires confirmation. Candidate navigation is disabled until a candidate exists.
6. Layout `display:grid` exposed fields marked `hidden`, including Dynamic filter on Static address groups. Explicit hidden state now wins throughout the UI.
7. Policy picker row clicks did nothing while object picker rows worked. Live and offline policy pickers now support the same whole-row, multi-select interaction.
8. Interface mapping options now accept each row's context-scoped target list rather than the union of targets from all scopes.
9. Empty XML Network/Device pages can render the shared Add modal from server-provided create schemas; no existing row or raw XML editing is required. A compact type selector is shown when several types are available. Subsequent edits restore the update endpoint instead of accidentally creating another entry.
10. Generic scalar fields preserve numeric zero instead of converting it to an empty string; Add/Edit enforce supplied required/max-length metadata, and protected values are never editable or submitted.
11. Invalid saved-filter strings and oversized SQLite resource IDs caused HTTP 500 responses. Typed query parsing and explicit resource-ID bounds now return a safe page or 404. Invalid/missing workspace pages, scopes and profile query IDs were also exercised without external target requests.

Tests: nine browser-DOM/event cases in `tests/test_frontend.cjs`, three Jinja render/parse tests in `tests/test_frontend_templates.py`, and four offline TestClient parameter tests in `tests/test_route_inputs.py`. The initial six event regressions, numeric-zero regression and malformed GET failures were reproduced before their fixes. DOM tests do not replace human-browser inspection or live target API validation.

## Remaining parity / usability debt

- Legacy family mapping, saved filters, bulk rename, enrichment/API-plan export, snippets, project roles and audit controls exist in the hidden migration control-center template. Except for the restored best-practice analysis, these are not reachable from the default project layout. Exposing them needs a compact navigation decision rather than rendering the whole old panel.
- Generic Network/Device/profile editors use schema-derived fields. Some member lists still allow freeform text instead of typed existing-object pickers; they are not a complete PAN-OS GUI clone.
- SCM server profiles are currently catalog-only references, while XML server profiles can be edited under Device. The SCM Network/Device API surface remains narrower than XML.
- Table search on workspace policies is intentionally split into a server-side full-inventory search and a client-side expression filter for the current page. Selection is page-local; operators should not mistake it for all matching rules across pages.
- Three separate picker implementations remain a regression risk. Shared behavior is now covered by executable event tests, but a later component consolidation would reduce future drift.

## Run the focused checks

Use the project Python test environment for:

```sh
python -m unittest discover -s tests -p test_frontend_templates.py -v
```

The DOM tests require Node.js and the pinned `jsdom` 26.1.0 development dependency. These packages are not copied into the production image:

```sh
npm ci --ignore-scripts
npm test
```

No target writes, deployment, credential changes or production data modifications were performed by this frontend worktree.
