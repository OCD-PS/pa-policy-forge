# PA Policy Forge audit — 7 September 2026

## Scope and method

Baseline `2574631`; three parallel reviewers covered backend/migration correctness, frontend/capability parity, and security. The primary agent integrated the fixes and used the real production browser on a separate audit project. Code checks and browser clicks are distinguished below; this is not a claim of complete PAN-OS GUI parity or an appliance-validated customer migration.

No firewall configuration writes or commits, Home target calls, password resets, certificate replacements, brute force, destructive scanning, or gateway policy changes were performed. Existing lab login and PAN TLS-verification exceptions were retained deliberately.

## Fixed

- Save confirmations shortened to **Opgeslagen** for object, policy and configuration workspace saves.
- Hidden required SCM fields no longer prevent standalone/Panorama profile forms from submitting. Hidden fields stay hidden across layout styles.
- Multi-selection, filtered range selection, row-click pickers and combined family/text filters behave consistently. Filtered-out policies are not added accidentally.
- Dead review links now open the appropriate collapsed analysis panel. Candidate navigation is inactive until output exists.
- Invalid saved-filter inputs and oversized database IDs no longer cause HTTP 500 errors.
- Scoped topology targets include all supported topology families and interface units. Saved mapping rows remain available for later changes. Mapping validates real interface/zone membership, not merely matching names.
- NAT and security zone inference stays conservative when some destinations, interfaces, scopes or routes cannot be resolved. No guessed resolution across ambiguous templates, FQDNs or NAT transformations.
- Rename/merge rewrites typed references, including NAT translations, without renaming unrelated descriptions or other object namespaces. SCM metadata is preserved.
- Empty Network/Device sections have server-owned Add schemas for 22 supported variants, including VLANs, routers, interface types, zones, selected network/authentication profiles and syslog server profiles. Invalid variants, field paths, references and protected fields are rejected.
- Add → Save → Edit keeps optional fields available through a virtual server-owned schema. Untouched fields do not add phantom XML/defaults; existing protected/unknown data and union choices are retained. Optional booleans explicitly offer **Niet ingesteld**.
- Enabled/disabled source status is informational in the review panel, not a requirement to disable every imported rule. The optional override remains explicit.
- Source-editor synchronization preserves unambiguous Check Point interface provenance and saved mapping identities. Current interface XML supplies subnet evidence, so changed/removed static IPs and DHCP never reuse stale source subnets. Ambiguous/renamed interfaces remain review-only and Check Point topology remains map-only.
- Migration workspace access now follows project permissions across exports, edits, immutable versions and deleted/recreated numeric project IDs. Historical migration snapshots fail closed when ownership cannot be established.
- Credential-bearing HTTP calls require HTTPS and do not follow redirects. PAN-OS calls use canonical `/api/`. OAuth errors are redacted; archive expansion is bounded before loading nested JSON.

The security evidence and accepted limits are in [SECURITY-AUDIT-20260907.md](../../SECURITY-AUDIT-20260907.md). The broader capability inventory and remaining UI parity debt are in [frontend-20260907.md](frontend-20260907.md).

## Remaining limits

- The full Check Point archive still needs genuine topology and policy-intent decisions. Its parser selects one gateway/cluster rather than modelling every install target in a multi-gateway archive.
- Ambiguous effective template stacks and operational dynamic routing/PBF decisions are not inferred.
- New GlobalProtect/certificate/secret-dependent construction is not complete; existing XML visibility must not be confused with complete typed creation support.
- SCM Network/Device coverage is narrower than XML. Some generic member fields remain freeform, and some older migration controls are still absent from the compact navigation. See the inventory rather than assuming all flavors now have identical coverage.
- No generated configuration was pushed to or commit-validated on an appliance in this audit.
